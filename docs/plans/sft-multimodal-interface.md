## Goal

Two trainer-facing capabilities, designed as benchmax interfaces (platform/trainer changes explicitly deferred):

1. **Multimodal messages in SFT** — OpenAI-style content-part lists are first-class in SFT dataset rows: validated by the schema, preserved through normalization/canonicalization, surfaced in the scorecard, demonstrated in the scaffold sample. RL-side multimodal (prompt transport, rollout proxy, reward reading) is owned by harbor-proper's native work (Geo3K) and is out of scope here.
2. **Env-less SFT** — supervised fine-tuning as a training mode with no environment: a dataset contract (OpenAI fine-tuning chat format) + local validation + upload/launch plumbing, anchored by a `main.py` project artifact.

## Approach

One message currency: everything new imports `Message`/`Messages` from `benchmax.envs.base.openai_types`. Multimodal is *not* a new type — a user message with `content: [{type: image_url}, {type: text}]` is already legal; the work is shared helpers plus the SFT dataset pathway (validation, canonicalization, preview). RL-side transport and consumer fixes are harbor's (r3). SFT is a dataset contract + CLI mode, never touching `envs/` beyond the alias import; project artifact stays `main.py` (reproducible record: data-prep code + configs + SDK calls), with `TRAINING_MODE = "sft"` as the explicit mode marker (fail loudly: a `main.py` with neither an env class nor a mode marker is an error).

Two contract principles added in r2:

- **One canonicalization boundary**: a single loader (`sft/dataset.py`) parses raw JSONL, normalizes legacy shapes, and retains per-row provenance. Validation and upload both consume its output. No path exists where un-normalized rows reach storage.
- **Explicit mode, not inferred**: `LoadedProject.training_mode: Literal["rl", "sft"]` is the mode contract; `env_class: type | None` is a consequence of the mode (`None` iff `sft`), never the signal.

**Rejected alternatives** (and why):

- *SFT via env subclass* (`SftDemonstrationEnv` pattern): envs are an RL concept; every hook is a stub; validate/launch semantics undefined. Kept in-tree untouched for now; deprecation happens with the platform-side trainer migration (out of scope).
- *prompt/completion-split row format*: subsumed by the single `messages` list (OpenAI fine-tuning format); awkward for multi-turn + tool demos. Split rows are **accepted as input** and normalized at the canonicalization boundary.
- *Reusing `traces/adapter.normalize_message` for SFT normalization*: lossy for multimodal content and the file is rewritten on harbor-proper — divergence trap. SFT normalization is self-contained with its own tests (per repo rule: shared utilities need dedicated tests).
- *Commit-level cherry-pick of harbor-proper's message change*: it lives inside the group-native-interface commit that was deliberately reverted off main; picking it would un-revert the WIP architecture. File-level picks instead.
- *Hand-porting harbor-proper's env contract files early* (r2): needs ~7 upstream files (`base/env.py`, `base/dataset.py`, `envs/dataset.py`, `envs/environment.py`, `envs/shared_types.py`, `envs/identity.py`, `envs/logging.py`) days before the merge lands them — dual-maintenance risk for zero schedule gain. Standing rule even though the slice that motivated it is gone.
- *Owning RL-side multimodal in this plan at all* (r3; supersedes r2's Geo3K-vs-Qwen analysis): harbor-proper ships native RL multimodal (Geo3K). Either variant — porting Qwen3OCR or adopting Geo3K as a reference — duplicates upstream work and drags the env-contract rewrite back into scope. (The r2 finding stands for the follow-up: Geo3K is content-shape prior art only — no SFT export, pre-baked data URIs, list-content-skipping reward.)
- *Custom `ContentPart` TypedDicts*: OpenAI SDK types already define the shapes; inventing parallel types re-creates the divergence this design removes.
- *`asset://` image references*: requires platform storage + trainer/rollout materialization — deferred. v1 transport is data URIs + https URLs (both work through the proxy and vLLM today).
- *Shoehorning SFT results into `ValidationReport`*: its fields are rollout-oriented. New `SftValidationReport` with the same gate semantics (`ok`, `__bool__`) so `main.py` gate code reads identically.

### 1. Content helpers

### 3. `benchmax/sft` package (dataset boundary, schema, validation)

New `src/benchmax/sft/`:
- `dataset.py` (r2 — the canonicalization boundary) — `load_sft_dataset(path) -> SftDataset`: reads **raw JSONL itself** (not `cli/_project.py:128` `_load_jsonl`, which drops blank lines, reindexes, and raises `ProjectError` on malformed JSON before any report could exist). Retains per-row `(source_path, physical_line)` provenance with 1-indexed physical lines counting blanks; malformed JSON becomes a per-line **error issue**, not an exception; normalization (below) applied on load. `canonical_jsonl(dataset) -> bytes` renders the canonical form for upload — the only serialization the upload path accepts. **Canonical row keys (r4)**: `messages` (required) plus the supported optional fields — top-level `tools` and per-assistant-message `weight` — preserved verbatim; canonicalization strips only the *legacy shapes*, never data the schema accepts.
- `schema.py` — row contract: `{"messages": [...]}`, optional `tools`, optional per-assistant-message `weight` (0|1). Per-row validation: role structure, ≥1 trained assistant turn, well-formed tool calls, well-formed content parts, JSON-serializability.
- `normalize.py` — legacy shapes → canonical rows (`prompt_messages`+`completion_messages` split, bare `prompt` string, flat tool-call format), **preserving** multimodal content parts. Self-contained. Invoked only by `dataset.py` — callers never see un-normalized rows.
- `validate.py` — `validate_sft_dataset(train: SftDataset, eval: SftDataset | None, max_seq_len=..., max_row_bytes=1 MiB) -> SftValidationReport` (frozen dataclass). Issues carry `(source_path, physical_line, severity, message)` with two severities: **error** (gate-failing) and **notice** (informational: e.g. `weight` present, per-row serialized size ≥ `max_row_bytes`). Report fields: issues, row counts, token-length stats (char/4 heuristic + rendered-length flagging), masking summary. **`ok` predicate (pinned, r2): `ok == (no error-severity issues) and (train row count ≥ 1)`** — an empty/absent train set is an error (mirrors `ValidationReport:719`'s "nothing ran is failure"); an empty eval set is a notice. `__bool__ == ok`.

Public surface (r2): `benchmax.sft` exports `load_sft_dataset`, `validate_sft_dataset`, `SftDataset`, `SftValidationReport`.

**Gate**: `uv run pytest tests/unit/sft` green — covers valid rows, each error class with **physical** line numbers asserted through blank lines and a malformed-JSON line, weight validation (notice severity), multimodal rows, split-format normalization round-trip, the row-size notice at the 1 MiB default, empty-train → `ok is False`, empty-eval → notice, and canonicalization-preservation tests: `canonical_jsonl(load_sft_dataset(legacy_split_file))` yields canonical-key rows with `tools`, tool calls, `weight`, and multimodal content parts all intact; ruff clean.
